## History Preservation

The new repository starts with an empty root commit. Each source `main` was fetched without tags, merged with `--allow-unrelated-histories -s ours --no-commit`, and imported with `git read-tree --prefix=frontend/ -u FETCH_HEAD` or `--prefix=backend/`. Each import was then committed as a two-parent merge. This is an unsquashed subtree-style import: every original source commit ID remains reachable from the new `main`.

The original trees exist at the import commits. A later commit flattens `frontend/frontend-kombat/` into `frontend/` and adds monorepo documentation and deployment configuration. Older commits keep their original paths. No history rewrite, squash, force push, nested `.git`, or submodule was used. Only `main` is intended for publication; unrelated source branch tips and tags are not included.

Both imported source tip hashes pass `git merge-base --is-ancestor <source-tip> main`. All source `main` ancestors are therefore retained unchanged.
